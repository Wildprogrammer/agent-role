# 宿主行为验证

行为冒烟只验证三件事：Agent 能返回自身 `agent_id`、默认主工作流名，以及“先完整加载主工作流”的第一动作。固定提示禁止工具调用，不执行业务任务，不读取外置配置正文，也不验证真实业务系统。

Hermes 完整启用采用 readiness-only：只回读模型/环境摘要、工作目录、单一 Gateway、目标平台禁用和路由状态，不发送真实消息，不启动主工作流。外部系统只使用其所属工作流已经提供的只读检查；没有入口时记录 `not_checked`，不发明命令。

验证结果分层记录：

- `verified`：静态文件、宿主发现和行为证据均通过。
- `partially_verified`：静态和发现通过，但宿主只能由用户提供后续行为证据。
- `failed`：已有证据明确不匹配。
- `outcome_unknown`：无法可靠确定写入或验证结果，必须先只读对账。

证据只保存会话/预设标识、固定 prompt SHA、响应 SHA 和解析后的三项结果；不保存凭据。

## 业务依赖就绪不等于身份冒烟通过

以上是现有 CLI 的文件、发现和身份验证状态，不覆盖业务工具接入；即使返回 `verified`，也不能据此声称 Jenkins 等业务能力可用。身份冒烟的“禁止工具调用”只约束该固定提示，不禁止另行开展已授权的只读依赖验证。

主 Agent 应按所选工作流及实际使用的子流程各自的依赖说明验证，不只检查 Jenkins，也不只读取 capability 名称列表：

- MCP 工作流：检查实际解释器/后端、完整握手与工具发现，再在目标 Agent 内进行范围明确的最小只读查询。
- CLI 或 Python 库工作流：检查实际运行环境、配套源码包和资源，以及目标 Agent 的命令/导入能力；不要求额外包装为 MCP。
- 纯 Skill 编排：检查目标宿主能否读取授权材料、模板及角色资源，不强加服务安装。
- 可选模型、文档格式或渠道：仅验证本次选用项；未选用不阻塞，降级运行则说明实际可用范围。

探测边界以所属工作流为准：有的 health 会调用本地模型，有的 query 会刷新数据库，不能仅凭命令名称认定为无写入。分别在现有交付说明中报告已通过、失败和未检查项；任一必要依赖缺失时明确写明“部署文件已就位，业务运行依赖未就绪”。不要伪造现有 verification.json 尚未支持的字段，也不要把接入失败隐藏在身份验证成功后面。以上复用原有依赖与部署确认，不新增逐项确认门。

例如 Jenkins 的依赖和三层验证以 `jenkins-operations` 的 `references/runtime-and-mcp-readiness.md` 为准；宿主适配器负责映射，独立运行副本负责交付现有 Hub 服务代码，不重写 Jenkins 业务协议。DSH/Hermes 支持请求中的 `host_options.mcp_servers`，精确写入仍纳入既有部署确认。CLI 回读映射后只标记 `configured_not_probed`，独立副本的握手和工具发现另记入 `static.runtime.mcp`，两者不混用。不会自动调用业务工具；配置 MCP 的部署即使身份通过也保持 `partially_verified`，真实工具验证证据另在交付说明中记录。本说明本身不授权宿主写入。
