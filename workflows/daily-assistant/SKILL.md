# 日报助手

## 用途与触发条件

将用户在对话中提供的当日任务和明确进展，整理为可维护的本地任务状态；
在用户明确请求时生成日报、月度禅道任务文字草案，或与运行时模板匹配的
本地导入文件。

## 非目标

不实现禅道账户、凭据、远端读取、创建、修改或删除；不写入 Obsidian；
不发布日报或上传文件；不在没有明确进展时猜测任务完成、工时、截止日期或
外部字段；不创建或启用真实提醒自动化。

## 输入

对新任务给出拆解、P0-P3 优先级建议与理由，以及项目、产品、模块、迭代的
分类建议。建议不阻断用户修改：用户对标题、拆解、优先级和分类的纠正优先，
并覆盖之前建议。

给出后续建议前读取已确认经验，但不把经验当作事实或阻断条件。只有用户明确
确认可复用的分类、优先级或耗时纠正，才合并写入 knowledge.md；单日任务、
执行记录和未确认的推断不能进入经验文件。

不持久化用户输入原文。状态缓存只保存规范化的任务字段、状态事件和结转所需
最小数据；状态事件中的摘要必须是助手归一化后的状态摘要，不能复制原始消息。
未收到新的进展时，保持最后一次已知状态；不得推断完成、耗时、截止日期或
外部系统字段。只有用户明确说明完成时才可将状态改为 done。

## 输出与命名规则

日报、月度草案和导入文件只在用户明确请求时生成；它们是本地交付物，不是
长期经验库。若用户要求写入文件，先确认输出目录和覆盖方式，并使用唯一
run ID 避免覆盖既有交付物。未提供禅道模板或表头及字段映射时，只输出月度
文字草案，不能声称它可以被禅道导入。

## 私有运行时边界

运行时必须提供 state_cache_path、knowledge_path 和时区；不要写死个人路径，
不要提交运行时文件。状态缓存用于当前任务和结转；knowledge.md 是唯一长期
经验文件，只保存已确认的分类、优先级和耗时经验。相同经验合并，冲突经验
替换，内容保持短小，不记录每日流水、原文或进展日志。

## 依赖和运行前检查

本工作流没有必选外部 capability。开始前只读检查运行时提供的状态缓存路径、
经验文件路径、时区和可选导入模板；路径不可写、时区未知或模板字段不完整时，
停止相应写入或导出动作并说明缺少的信息。不要将用户的个人路径写入通用
工作流。

## 系统修改与权限影响

本工作流默认只读聊天上下文并写入已确认的本地私有运行时文件。状态缓存、
knowledge.md 和用户明确请求的本地交付物是唯一允许写入的范围。不安装软件，
不修改宿主、包管理器、日程、提醒、Obsidian 或禅道配置。

## 执行步骤

1. 将任务规范化，给出拆解、优先级理由和四维分类建议。
2. 只在用户提供进展时记录显式状态变化；用户没有更新时不改变状态。
3. 在运行时时区的 24:00 执行幂等结转：统计未完成项并转至下一日；不生成日报。
4. 日报和月度草案仅在用户明确请求时生成。
5. 只有运行时提供禅道导入模板或表头及字段映射时，生成匹配模板的本地导入
   文件；没有模板时只交付文字草案。

## 提醒与外部系统

建议提醒时点为 10:00、11:30、14:30、16:10、17:10，详见
references/automation.md。工作流不得创建或启用真实提醒自动化；如需创建宿主
心跳、日程或计划任务，必须先获得用户另行明确确认。

不写入 Obsidian，不直连禅道，不读取或修改远端禅道数据，不发布日报，
不上传文件。

## 人工确认门

用户确认优先级、拆解或分类时，纠正值覆盖建议。创建实际提醒自动化前必须
由用户另行明确确认；生成日报、月度草案、导入文件或本地文件前，也必须有
本次明确请求。没有请求不能以时间点、旧消息或默认规则替代确认。

## 失败恢复

状态缓存写入被中断时，保留上一次完整文件并通过同目录临时文件原子替换恢复。
模板缺失、字段映射不完整、路径不可写或时区未知时，不创建部分导入文件；
保留规范化状态，向用户说明所需输入。任何外部系统不可用都不触发替代性的
远端连接或 GUI 操作。

## 重跑、幂等与覆盖策略

相同任务 ID 更新现有规范化任务，不复制原文。每个日期的 24:00 结转只执行
一次；已结转日期重跑时不再次移动任务。重新生成日报或月度草案只读取当前
规范化状态；写文件时必须使用用户确认的覆盖策略和唯一 run ID。

## 验收标准

任务、状态、结转、日报、月度文字草案和模板绑定导入文件都来自规范化的
本地数据。无用户请求、无导入模板或无自动化授权时，工作流不生成相应输出、
不执行外部动作。

## 清理方式

普通清理只能移除调用方明确指定的、可重建的私有状态缓存临时文件。不得自动
删除 knowledge.md、用户请求生成的日报/月度草案/导入文件，或任何用户目录。
删除交付物必须由用户提供精确路径并再次确认。
